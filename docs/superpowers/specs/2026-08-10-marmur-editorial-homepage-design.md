# Marmúr — редакційна головна сторінка

**Дата:** 2026-08-10
**Статус:** затверджено до реалізації
**Гілка:** `feat/editorial-homepage`

## Мета

Перетворити головну з «інтернет-магазину квітів» на «сучасний квітковий бренд,
який має інтернет-магазин». Кожен скрол має відчуватись як перегортання
сторінки у квітковому журналі.

Ритм сторінки чергується **PRODUCT → IMAGE → STORY → PRODUCT → IMAGE →
EMOTION**, а не **SECTION → CARDS → SECTION → CARDS**.

## Не входить у скоуп

- Реальна фотозйомка студії (замість неї — порожні кадри з брифами, див. §10).
- Заміна вертикального рілза в hero на горизонтальне відео.
- Сторінки, крім головної та `catalog.vue` (лише параметр `budget`).
- Зміна токенів дизайн-системи. Нових `Ds*` компонентів не додаємо.

## Поточний стан

`pages/prototype/index.vue` — hero → рейка фактів → `01 —` Букети на сьогодні →
`02 —` Каталог → темний вислів → `03 —` Майстерня → `04 —` Відгуки → темний CTA.

Дизайн-система вже існує: токени в `apps/web/app/assets/css/design-system/`,
21 компонент у `apps/web/app/components/ds/`. Правила — `docs/design-system.md`.

`proto/home/VariantA|B|C.vue` (733 рядки) — мертвий код, на них немає жодного
посилання.

## Затверджені рішення

### 1. Відсутня фотографія — порожні кадри з брифами

Секції 7 і 10 потребують зйомки процесу (руки флористки, пакування, стрічки,
листівки, ранкове привезення), якої в репозиторії немає: усі 21 файл у
`public/prototype/` — це готові букети й товари.

Використовуємо вбудований плейсхолдер `DsEditorialImage`: рівне поле `sand`
з підписом, **що саме тут має бути знято**. Порожній кадр чесніший за стокове
фото, а секція «За кадром» водночас працює як список зйомки для фотографа.
Верстка фінальна — пізніше підставляється лише файл.

### 2. Заголовок вітрини лишається динамічним

Бриф просить «Квіти сьогодні». Поточний заголовок динамічний: `todayWord`
перемикається на «завтра» після відсічки о 18:00 (`protoDelivery.cutoffHour`).

Беремо формулювання брифу, але зберігаємо правило: **`Квіти {todayWord}`** →
«Квіти сьогодні» до 18:00, «Квіти завтра» після. Підзаголовок «Те, що наші
флористи зібрали сьогодні вранці.» правдивий в обох випадках.

Статичний заголовок брехав би вечірньому відвідувачу.

### 3. Приводи ведуть на реальні фільтри

Приводи з §9 («для неї», «просто так»…) не існують як категорії — у каталозі
лише `mix / mono / baskets / bride / gift`. Кожен привід веде на подання
каталогу, яке реально працює:

| Привід                       | Посилання                       |
| ---------------------------- | ------------------------------- |
| для неї                      | `/catalog?category=mix`         |
| для нього                    | `/catalog?category=mono`        |
| на день народження           | `/catalog?category=baskets`     |
| просто так                   | `/catalog?budget=lt1000`        |
| для особливого вечора        | `/catalog?budget=gt1500`        |
| коли не знаєш, що сказати    | `/catalog`                      |

**Каталог поки не читає `budget`,** тому його треба додати — див. «Зміни в
каталозі». Без цього два з шести посилань мовчки вели б на нефільтрований
каталог.

### 4. Відгуки — стос на всю ширину, без каруселі

Карусель із автопрокруткою порушила б §25 (ніщо на сайті не анімується
постійно). Замість неї — **три відгуки поспіль**, кожен на всю ширину з
великим повітрям, поява через `DsReveal` при скролі. «По одному за раз»
досягається скролом, а не контролами; нічого не сховано за кліком.

Беремо існуючі відгуки з `protoReviews` — **не вигадуємо нових цитат і не
приписуємо їх реальним іменам**. Порядок: Андрій → Марта → Олена. Ігор
(«о 21:00 замовив — о 10:30 привезли») випадає: швидкість уже названа в рейці
фактів.

### 5. Нумерація лишається тільки на торгових секціях

Дванадцять пронумерованих секцій читались би як зміст і зруйнували б журнальне
відчуття. Нумеруємо лише чотири секції, де можна купити: `01 —` вітрина,
`02 —` колекції, `03 —` добірка, `04 —` приводи. Редакційні та емоційні секції
без номерів. Прийом виживає й починає щось означати: **пронумеровано = тут
купують**.

### 6. Фінальний CTA — на `--color-brand`

`#3A2923` із брифу — це вже токен: `--espresso` / `--color-brand`. Темні
редакційні врізки лишаються на `--chocolate` `#261B17`. Фінальна секція стає
теплішим темним, ніж усі попередні, — виключно наявними токенами. Відхилення
документувати не треба.

### 7. Hero втрачає рядок про доставку

Бриф хоче знак + один рядок + один CTA. Відсічка о 18:00 і поріг безкоштовної
доставки їдуть на екран нижче — у рейку фактів, де вони вже є. Нічого не
втрачено, hero перестає конкурувати сам із собою.

Позначку «Чернетка: вертикальний рілз, кропнутий» лишаємо — відео досі
тимчасове, і це той самий принцип чесності, що й порожні кадри.

### 8. Колекції показують реальні категорії

Перелік у брифі (Букети / Моно / Преміум / Для особливого дня) поданий як
приклад. Беремо реальні чотири — Мікс-букети, Моно-букети, Корзини та коробки,
Подарунки — і даємо кожній власну візуальну ідентичність різним співвідношенням
кадру й масштабом шрифту. Саме це створює відчуття виставки.

## Відповідність дизайн-системі

Перевірити перед здачею:

- Кольори — лише сім наявних; нових акцентів немає
- Радіуси 0–6px; `9999px` не зустрічається
- Тіней немає; градієнт лише як scrim над фото
- Капс — тільки `ds-meta` (11–13px, tracking `.14em`); заголовки не капсом
- Жодного повторюваного «заголовок / текст / три картки / кнопка»
- Рух 200–500ms, `--ease-standard`; нічого не анімується постійно
- Іконки — лише з дозволеного набору Lucide; емодзі немає
- Голос: без окличних знаків, терміновості та знижкової лексики
- Нових `Ds*` компонентів не додано
